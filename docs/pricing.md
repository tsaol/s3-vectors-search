# S3 Vectors 怎么收费

> 价格来自 AWS Price List API（发布时间 2026-11-21）和 [Amazon S3 定价页](https://aws.amazon.com/s3/pricing/)。报价前请再查一次。

## 1. 五项费用

S3 Vectors 没有固定费用，也不用开机器，只按用量收这五项：

| 项目 | 美东（弗吉尼亚北部） | 法兰克福 | 怎么算 |
|---|---|---|---|
| 存储 | $0.06 / GB·月 | $0.064 / GB·月 | 向量 + key + 全部元数据 |
| 写入（PUT） | $0.20 / GB | $0.214 / GB | 写入的数据量，**每次请求最少按 128 KB 算** |
| 查询请求 | $2.50 / 百万次 | $2.70 / 百万次 | 每次 QueryVectors |
| 查询处理量 | 见下表，按 TB 阶梯收费 | 见下表 | 被查的**索引大小** × 每个向量的"处理大小" |
| 返回数据 | $0.01 / GB | $0.01 / GB | 每次查询前 512 KB 免费；每条结果最少按 256 字节算 |

另外，价目表里还有其他向量 API 请求的费用（"Tier1 / Tier2 Vectors API Requests"）：美东 $0.055 / 千次，法兰克福 $0.059 / 千次。定价页没有说明具体是哪些 API，用量大时请看账单明细。

**查询处理量**是重点，按**每个索引**里的向量数分三档收费（美东价格）：

| 每个索引里的向量 | $/TB |
|---|---|
| 前 10 万个 | $0.004 |
| 10 万 ~ 1,000 万 | $0.002 |
| 1,000 万以上 | $0.0004 |

法兰克福的价格大约高 7%（价目表里每 GB 的价格：$0.000004185 / $0.000002093 / $0.000000419）。全文检索的文本按单一价格收费：**$0.00012 / TB**。

## 2. 每个向量算多大

- 向量：维度 × 4 字节（1024 维 = 4 KB）
- key：每个字符 1 字节
- 元数据：实际大小
- **存储**算全部。
- **查询处理量**只算：向量 + key + **可过滤的**元数据 + 全文检索字段。**不可过滤、也不做全文检索的元数据不算**。
- 一个字段如果既可过滤又能全文检索，存储和处理量都算两次。

这就是为什么原文片段要放进 `nonFilterableMetadataKeys`：放在那里，它只占存储，不增加每次查询的费用。

## 3. 用 AWS 自己的例子验证

`tools/cost_estimate.py` 按定价页的算法计算，测试里用 AWS 定价页的例子做了验证（`tests/test_cost.py`）：

- **例 1**：1,000 万个向量，分在 40 个索引里（每个 25 万），1024 维，1 KB 可过滤元数据 + 1 KB 不可过滤元数据，每月 100 万次查询，每 6 个月全量写一次 → **$11.38 / 月**
- **例 3**：1,000 万个向量放在 1 个索引里，每个向量带 3 KB 的全文检索文本，每月 100 万次混合检索 → **$107.79 / 月**，另加一次性回填费 $5.72

注意两个例子的差别：每个索引的大小决定了每次查询要"处理"多少数据。**把数据分到多个小索引，每次只查一个**，会便宜很多。但前提是你的查询本来就只需要查其中一部分，比如按部门、按租户分。

## 4. 本 repo 场景的估算（假设，用于说明量级）

假设：

- 文件抽取、切分后共 2,000 万个片段（600 字一段）
- 1024 维 Titan V2；每个向量 1 KB 可过滤元数据（路径、部门、权限组……）
- 片段原文 1.8 KB（600 个汉字 × 3 字节），设为不可过滤 + 全文检索
- 全部放在 1 个索引；每月 100 万次混合检索；每月大约有 5% 的数据被重写

```
python tools/cost_estimate.py --vectors 20000000 --text-kb 1.8 --filterable-kb 1 \
    --queries 1000000 --uploads-per-month 0.05 --region eu-central-1
```

结果（法兰克福，每月）：

- 存储约 133 GB → **$8.51**
- 重写 → $1.42
- 查询处理 → $124.87；全文检索 $4.02；查询请求 $2.70
- **合计约 $142 / 月**

其中查询处理量占了大头。如果按部门把索引分开，每次查询只查自己部门的索引，这一项会明显下降。

**不在 S3 Vectors 账单里的费用**：embedding 调用（Bedrock 按 token 收费）、OCR（Textract 按页收费）、Lambda、SQS、回答用的大模型。**对于百 TB 级的回填，这几项通常比 S3 Vectors 本身贵得多**，要单独估算（需求 NFR-3）。

## 5. 省钱要点

1. 原文片段、长描述放进 `nonFilterableMetadataKeys`，不计入查询处理量。
2. 能按租户、部门分开的，就分成多个索引，每次只查需要的那个。
3. 批量写入：每次最多 500 个向量，避开 128 KB 的最低收费。
4. 不要频繁覆盖同一批 key：删除和覆盖的数据会暂时计入索引大小。
5. topK 不要设得太大，返回元数据时只取需要的字段；每次查询前 512 KB 免费。
